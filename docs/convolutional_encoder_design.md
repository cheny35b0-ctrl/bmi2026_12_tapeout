# 畳み込み符号化機能 設計ドキュメント

## 1. 概要

本設計は、通信データの信頼性向上のため、畳み込み符号化機能をBMIディジタル回路に追加するものである。符号化はディジタル回路側で実施し、復号化はFPGA側でビタビ復号を使用して行う。

## 2. 要件定義

### 2.1 畳み込み符号パラメータ
- **符号化率（Code Rate）**: 1/2
- **拘束長（Constraint Length）**: K = 3
- **生成多項式（Generator Polynomials）**: G0 = 7 (111₂), G1 = 5 (101₂)
- **自由距離（Free Distance）**: dfree = 5
- **理論上の誤り訂正能力**: ⌊(dfree - 1) / 2⌋ = 2ビット
  - 注意: これは理論上の最大値であり、実際の訂正能力は誤りの位置やパターン、チャネル特性に依存します
  - バースト誤りや特定の誤りパターンでは期待通り動作しない場合があります
  - 必ず実測（BER測定）で確認すること
- **終端処理**: ゼロ終端（zero termination）方式
  - 入力末尾にK-1個（2ビット）の0を付加してエンコーダ状態を`00`に戻す
  - Tail-bitingとは異なる方式（初期状態と最終状態を合わせる必要なし）

### 2.2 適用範囲
以下のフィールドに対して符号化を適用：
- ADDRESS（8bit）
- TYPE（2bit）
- DATA（20bit）
- 終端ビット（2bit）

**合計**: 32bit入力 → 64bit出力

### 2.3 制御方式
- **制御信号**: `command[18]`
  - `1'b1`: 符号化有効
  - `1'b0`: 符号化無効（スルーモード）
- FPGAから事前にコマンド送信により設定

**重要な制約:**
- `ENCODE_ENABLE`（`command[18]`）は**フレーム送出開始時にラッチ**され、フレーム送信中は固定される
- フレーム途中での変更は不整合を引き起こすため禁止
- 実装方法: `ENABLE`信号の立ち上がり時点で`ENCODE_ENABLE`の値をレジスタに保持し、次の`ENABLE`立ち上がりまで変更不可とする

### 2.4 データフロー
```
入力: {ADDRESS[7:0], TYPE[1:0], DATA[19:0], 2'b00} (32bit)
       ↓
畳み込み符号化器 (K=3, rate 1/2, (7,5))
       ↓
出力: 64bit符号化データ
       ↓
シリアル送信
```

### 2.5 ビット順序の定義
**入力順序（MSB first）:**
- 入力ビットは`ADDRESS[7]`から開始し、`ADDRESS[0]`, `TYPE[1]`, `TYPE[0]`, `DATA[19]`, ..., `DATA[0]`, 終端ビット`0`, `0`の順で処理

**出力順序（シリアル送信）:**
- 各入力ビットに対して2ビット（c0, c1）を生成
- 送信順序: `c0`を先に送信、次に`c1`を送信
- 例: 1番目の入力ビット（ADDRESS[7]）→ 出力（c0[0], c1[0]）を順次送信
- FPGA側ビタビ復号器は同じ順序（c0, c1のペア）で受信する前提

**重要:** FPGA側のパスメトリック計算は、この出力順序と厳密に一致させる必要があります。

## 3. 畳み込み符号化器の詳細

### 3.1 符号化器の構造

```
入力ビット d[k] → [S1][S0] → G0 (111) → 出力ビット c0[k]
                      ↓
                    G1 (101) → 出力ビット c1[k]
```

- **S0, S1**: 2ビットシフトレジスタ（内部状態）
- **初期状態**: `S1=0, S0=0`
- **終端状態**: `S1=0, S0=0`（ゼロ終端により保証）

### 3.2 生成多項式の実装

**G0 = 111₂ (7₈)**
```verilog
c0[k] = d[k] ⊕ S0 ⊕ S1
```

**G1 = 101₂ (5₈)**
```verilog
c1[k] = d[k] ⊕ S1
```

### 3.3 符号化手順

1. 入力32bitをパラレルで受け取る
2. 各ビットを順次処理（MSBファースト: ADDRESS[7]から開始）
3. 各入力ビットに対して2ビット出力（c0, c1）
4. 64bit符号化データを生成
5. シフトレジスタへ転送

## 5. モジュール設計

### 5.1 新規モジュール

#### 5.1.1 CONV_ENCODER.v
**機能**: K=3, rate 1/2 畳み込み符号化器

**入力**:
- `CLK`: システムクロック
- `POR`: パワーオンリセット
- `START`: 符号化開始信号
- `DATA_IN[31:0]`: 入力データ（パラレル）

**出力**:
- `DATA_OUT[63:0]`: 符号化後データ（パラレル）
- `DONE`: 符号化完了信号

**内部レジスタ**:
- `state[1:0]`: シフトレジスタ（S1, S0）
- `bit_counter[5:0]`: ビットカウンタ（0～31）
- `encoded_data[63:0]`: 出力バッファ

**動作**:
1. `START`でリセット、`bit_counter = 0`、`state = 2'b00`
2. 毎CLKで1ビット処理
3. `DATA_IN[31 - bit_counter]`を入力
4. G0, G1で2ビット生成し、`encoded_data`に格納
5. `bit_counter`をインクリメント
6. **`bit_counter == 31`で`DONE`アサート**
   - 注意: 入力32ビット（30bit + 終端2bit）の処理完了を示す
   - この時点でエンコーダの状態は`00`に戻っている（ゼロ終端の効果）

#### 5.1.2 ENCODER_CONTROL.v
**機能**: 符号化ON/OFFの制御とデータセレクタ

**入力**:
- `CLK`, `POR`
- `ENCODE_ENABLE`: `command[18]`
- `ADDRESS[7:0]`, `TYPE[1:0]`, `DATA[19:0]`
- `ENCODED_DATA[63:0]`: 符号化後データ

**出力**:
- `OUTPUT_DATA[63:0]`: 選択されたデータ（符号化 or 非符号化）
- `DATA_LENGTH[6:0]`: データ長（30 or 64）

**動作**:
```verilog
if (ENCODE_ENABLE) begin
    OUTPUT_DATA = ENCODED_DATA;
    DATA_LENGTH = 7'd64;
end else begin
    OUTPUT_DATA = {34'b0, ADDRESS, TYPE, DATA};
    DATA_LENGTH = 7'd30;
end
```

### 5.2 修正が必要なモジュール

#### 5.2.1 SELECT.v
**変更内容**: 状態遷移タイミングの調整

現行の`comcon_out`閾値:
```verilog
counter:  comcon_out >= 8'd33
address:  comcon_out >= 8'd41
type:     comcon_out >= 8'd43
shift:    comcon_out >= 8'd63
stop:     comcon_out >= 8'd66
```

新しい閾値（符号化ON時）:
```verilog
counter:  comcon_out >= 8'd33
encode:   comcon_out >= 8'd97  // +64bit
stop:     comcon_out >= 8'd100 // +34bit
```

**追加入力**:
- `ENCODE_ENABLE`: `command[18]`
- `ENCODED_DATA[63:0]`: 符号化後データ

**状態の追加/変更**:
```verilog
localparam none = 3'b000, counter = 3'b001,
           address = 3'b010, type = 3'b011,
           shift = 3'b100, encode = 3'b101,  // ← 新規追加
           stop = 3'b110, fin = 3'b111;
```

動的に状態遷移を切り替え：
```verilog
if (ENCODE_ENABLE)
    counter → encode → stop → fin
else
    counter → address → type → shift → stop → fin
```

#### 5.2.2 SHIFT_REG.v
**変更内容**: 64bitシフトレジスタへの拡張

現行:
```verilog
input [19:0] DATA,
reg [20:0] shift_reg;  // 20bit + 1bit (LSB出力用)
```

新規:
```verilog
input [63:0] DATA,
input [6:0] DATA_LENGTH,  // データ長（30 or 64）
input ENCODE_ENABLE,  // 符号化ON/OFFフラグ
reg [63:0] shift_reg;  // 64bitシフトレジスタ
```

**動作**:
- `ENCODE_ENABLE`に応じて30bitまたは64bitのデータをロード
- **符号化OFF時**: `{34'b0, DATA[29:0]}`をロード
  - 64bitシフトレジスタに30bitデータのみ格納（上位34bitは未使用）
  - 注意: 64bitレジスタ幅のうち30bitしか使用しないが、これは仕様上問題なし
  - 30bitシフト完了後は`shift_reg = 64'b0`となる
- **符号化ON時**: `DATA[63:0]`全体をロード（64bit全てを使用）
- 毎`CLK50`で1bitシフト動作（`shift_reg >>= 1`）
- `S_OUT`は常に`shift_reg[0]`を出力

**設計判断**:
- 符号化ON/OFFで異なるシフトレジスタ幅を持つ代わりに、常に64bitレジスタを使用
- 符号化OFF時は上位ビットが未使用となるが、回路の統一性とデバッグの容易さを優先

#### 5.2.3 COM_CON_TOP.v
**変更内容**: 符号化器モジュールの統合

**追加接続**:
```verilog
wire ENCODE_ENABLE;
wire [31:0] encoder_input;
wire [63:0] encoder_output;
wire [63:0] output_data;

// 符号化イネーブル（外部から設定済みと仮定）
// 実際にはTOPモジュールでcommand[18]を渡す
assign ENCODE_ENABLE = /* command[18] from TOP */;

// 符号化入力データの準備
assign encoder_input = {ADDRESS[7:0], TYPE[1:0], DATA[19:0], 2'b00};

// 畳み込み符号化器のインスタンス化
CONV_ENCODER CONV_ENCODER(
    .CLK(CLK),
    .POR(POR),
    .START(state_comcon == counter && CLK50),
    .DATA_IN(encoder_input),
    .DATA_OUT(encoder_output),
    .DONE()
);

// データセレクタ
ENCODER_CONTROL ENCODER_CONTROL(
    .ENCODE_ENABLE(ENCODE_ENABLE),
    .ADDRESS(ADDRESS),
    .TYPE(TYPE),
    .DATA(DATA),
    .ENCODED_DATA(encoder_output),
    .OUTPUT_DATA(output_data),
    .DATA_LENGTH(data_length)
);

// SHIFT_REGへの接続
SHIFT_REG SHIFT_REG(
    .CLK(CLK),
    .CLK50(CLK50),
    .POR(POR),
    .ADC_STATE(ADC_STATE),
    .ENABLE(ENABLE),
    .state(state_comcon),
    .DATA(output_data),
    .DATA_LENGTH(data_length),
    .S_OUT(S_OUT)
);
```

## 7. 復号化（FPGA側）

### 7.1 ビタビ復号アルゴリズム
- **トレリス段数**: 34段（入力30bit + 終端2bit + パス初期化2bit = 30 + (K-1) + (K-1) = 34）
  - ゼロ終端により、トレリス長は入力ビット数 + (K-1)になります
  - 実装注意: デコーダは34段分のトレリス展開が必要
- **状態数**: 4状態（2^(K-1) = 2^2 = 4）
- **パスメトリック更新**: 毎2ビット受信時（c0, c1のペア）
- **トレースバック長**: 15段（推奨値: 5×K = 5×3 = 15）
  - 一般的な経験則として、トレースバック長は約4～5×Kが推奨されます
  - K=3の場合、15段のトレースバックで十分な復号性能が得られます

### 7.2 復号手順
1. 64bit符号化データを受信
2. 2ビットずつビタビ復号処理
3. トレースバックで32bit元データを復元
4. 終端2bitを除去して30bitデータを取得
5. ADDRESS, TYPE, DATAに分離

### 7.3 期待性能
- **理論上の誤り訂正能力**: 最大2ビット（自由距離dfree=5による）
- **符号化利得**: 約3～4dB（AWGN環境下の理論値）
  - **重要**: 実際の利得は以下に依存するため、必ずシミュレーション/実測で確認すること
    - ビタビ復号器の実装品質（パスメトリック計算の精度、量子化ビット数）
    - チャネル特性（AWGN、フェージング、バースト誤り等）
    - 送受信システムのSNR
  - **推奨**: AWGN環境でBER vs Eb/N0曲線を測定し、理論値と比較
- **復号遅延**: トレースバック長により約15CLK（トレースバック実行時）
- **バースト誤り耐性**: K=3の短い拘束長では長いバーストに弱い
  - 対策: インターリーバの追加、またはCRC+ARQによる再送制御を検討

## 8. 検証計画

### 8.1 単体テスト

#### CONV_ENCODER.v
**テストベクトルと期待出力:**

**テストベクトル1**: `32'h0000_0000` （全ビット0）
- 初期状態: `state = 2'b00`
- 入力全て0なので、状態は常に`00`のまま
- 期待出力: `64'h0000_0000_0000_0000`（全ビット0）

**テストベクトル2**: `32'hFFFF_FFFF` （全ビット1、ただし終端2bitは0）
- 実際の入力: `32'h3FFF_FFFF`（下位2bitは0で終端）
- 期待出力: K=3, G=(7,5)の符号化テーブルに基づく出力
- 終端により最終状態は`00`に戻る

**テストベクトル3**: `32'hAAAA_AAAA` （交互パターン、終端2bitは0）
- 実際の入力: `32'h2AAA_AAAA`（下位2bitは0で終端）
- 期待出力: 交互パターンの符号化結果
- 状態遷移: `00 → 01 → 10 → 01 → 10 → ... → 00`

**テストベクトル4**: `32'h0000_0001` （最下位ビットのみ1、その後0）
- 初期状態から1ビット入力後、31ビットの0が続く
- 期待出力: 最初の2ビットのみ非0、残りはほぼ0
- 終端により最終状態は`00`

**検証項目:**
- 終端処理の確認（最終状態が`00`になること）
- 各テストベクトルで64bit出力が正しく生成されること

## 10. リスクと対策

### 10.1 タイミング違反
**リスク**: 符号化処理による遅延増加
**対策**: パイプライン化、またはクロック周波数調整

### 10.2 リソース使用量
**リスク**: 64bitシフトレジスタによるゲート数増加
**対策**: リソース見積もりと最適化

### 10.3 デバッグ困難性
**リスク**: 符号化データの目視確認が困難
**対策**: ENCODE_ENABLEによるON/OFF機能で段階的検証

### 10.4 FPGA復号器の複雑性
**リスク**: ビタビ復号の実装難易度
**対策**: 既存IPコアの活用、または段階的実装

### 10.5 フレーム同期の堅牢性
**リスク**: 受信側が符号化ON/OFFを誤判定する可能性
**対策**:
- **推奨1**: フレームヘッダに符号化フラグビットを追加
  - 例: スタートビット直後に1ビット追加（`1`=符号化ON、`0`=符号化OFF）
  - 受信側はこのフラグを読んで復号モードを切り替え
- **推奨2**: 符号化ON/OFFで異なるプリアンブルパターンを使用
  - 受信側がプリアンブルを検出してモードを判別
- **推奨3**: 固定的に符号化ONで運用（最もシンプル）
  - デバッグ時のみ`command[18]=0`で符号化OFFを使用

### 10.6 comcon_outカウンタの閾値オフバイワン
**リスク**: 状態遷移タイミングが1サイクルずれる可能性
**対策**:
- 各閾値の意味（`>=`か`>`か、境界条件）をコメントで明記
- シミュレーションで波形を詳細に確認
- 例: `counter: comcon_out >= 8'd33` は「32クロックのスタートカウント完了後」を意味
